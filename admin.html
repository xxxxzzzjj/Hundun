🔗 公告页顶部跳转按钮
每行一个按钮，格式：按钮名称|目标（竖线分隔）。目标可以两种：
· 外部网址：必须 http:// 或 https:// 开头 → 点开是新标签网页
· 图片：填项目目录里的相对路径（如 公告图.png、imgs/notice/a.png）， 或者直接填 https 图片外链（如 https://xxx.com/a.jpg） → 点开全屏看原图，玩家手机上可双指放大
※ 用相对路径时，图片要和 index.html 一起上传到网站（放同一目录或子目录都行）。

留空 = 玩家端完全不显示这一栏。

📅 每日打卡奖励（每天默认给）
💡 玩家每天第一次点击"签到打卡"时自动发放上述所有奖励。
⚠️ item_id 必须是"道具管理→仓库区"里已存在的道具 ID；qty 是发放数量（背包按数量叠加）。
⚠️ 今日打卡清空
把所有玩家今天的打卡记录清空（lastCheckin 设为空），已打卡的玩家可重新打卡领奖。慎用！
🧹 清理玩家背包冗余快照
清空所有玩家 inventory 文档上的 name/desc/icon 冗余快照字段。
现在背包每次拉取都从道具定义取最新值，inventory 上的快照是冗余数据，清理后玩家看到的内容不会变，只会省一些存储。
⚠️ 仅清理 name/desc/icon 三个字段，不动 qty/uid/玩家 ID/时间戳等玩家私有数据。
🔧 修复背包归属（治「赠送成功但背包里看不到」）
老账号的背包数据可能缺少归属标识（player_uid），于是道具虽然已经写进库、玩家的背包里却查不出来。
这个修复会把它们补正到玩家的真实 uid，并把同一道具的重复行合并成一条（数量相加，不会丢道具）。
ID 留空 = 修复全部玩家；单次处理有时间上限，没跑完可以再点一次。
🧹 自动清理云端旧数据
下面这 9 张表是只增不删的，跑久了会一直吃云库空间。开启后系统会在玩家心跳时 顺带自动清理过期数据：不额外增加云函数调用次数，全服每 N 小时才真正跑一次，每张表单次最多处理固定条数。
⚠️ 只删早于保留天数的记录，当天 / 进行中的数据不会被碰；找不到的表等于 0 条，不会报错。

商人 · 宝箱刷新
· 玩家心跳时顺便检查：距上次自动备份超过设定小时数，就静默备份一份（约 0.2 秒/人）
· 压力分摊到一整天，不会集中处理全服，不影响流畅度
· 备份内容：属性/玄币/健康 + 背包 + 称号 + 副业 + 打工 + 种田 + 技能 + 门派绑定
· 手动备份（玩家列表「💾 备份」按钮）不受份数限制，永久保留
· 立即消失：第一个到达的玩家拿走，地图上马上消失
· N 分钟消失：被拿走后地图上仍显示（可做变暗），N 分钟后消失，期间别人不能再拿
· N 次消失：可被 N 个不同玩家各拿一次（同一人只能拿一次），拿满 N 次后消失
💡 宝箱只出现在「已启用 + 已配格子」的地点上（没配格子的格子 = 未开通区域，不会刷）
